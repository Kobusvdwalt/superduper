# Health sync contract (v1)

How a client pushes health data, and what the API guarantees. Both sides are tested
against the fixtures in `contracts/health-connect/v1/`.

## Transport

`POST /api/graphql` with `Authorization: Bearer <client token>`.

```graphql
mutation HealthSync($input: HealthSyncInput!) {
  health {
    sync(input: $input) {
      batchId
      replayed
      acceptedRecords
      acceptedDeletions
    }
  }
}

input HealthSyncInput {
  batchId: UUID!
  schemaVersion: Int!
  records: [HealthRecordInput!]!
  deletions: [HealthRecordDeletionInput!]!
}

input HealthRecordInput {
  origin: HealthOrigin!
  recordType: String!
  sourceRecordId: String!
  dataOrigin: String
  startTime: DateTime!
  endTime: DateTime
  startZoneOffsetSeconds: Int
  endZoneOffsetSeconds: Int
  modifiedAt: DateTime!
  payload: JSON!
}

input HealthRecordDeletionInput {
  origin: HealthOrigin!
  recordType: String!
  sourceRecordId: String!
  deletedAt: DateTime!
}

enum HealthOrigin {
  HEALTH_CONNECT
}
```

| Field            | Meaning                                                                   |
| ---------------- | ------------------------------------------------------------------------- |
| `batchId`        | Generated by the client once per batch; the idempotency key.              |
| `schemaVersion`  | Version of the payload rules below. Currently `1`.                        |
| `origin`         | The platform store the record was read from.                              |
| `recordType`     | The origin's own type name, for example `HeartRateRecord`.                |
| `sourceRecordId` | The origin's stable record id. Unique per client, origin and record type. |
| `dataOrigin`     | The app that wrote the record, for example an Android package name.       |
| `startTime`      | Start of an interval, or the instant of a point record.                   |
| `endTime`        | End of an interval. Null for point records.                               |
| `modifiedAt`     | The origin's last-modified time for the record.                           |
| `payload`        | The complete record, following the payload rules.                         |

## Server guarantees

- A batch is applied atomically, one batch at a time per client.
- Replaying a `batchId` with identical content succeeds with `replayed: true` and changes
  nothing. The same `batchId` with different content fails with `CONFLICT`.
- A record replaces the stored one only when its `modifiedAt` is newer. Every accepted
  payload is also appended to the version history.
- Deletions are soft. A deletion is not undone by a record whose `modifiedAt` is older than
  `deletedAt`.
- A record is accepted whether or not the API can project it into typed tables. Unknown
  `recordType` values are stored raw.
- Limits: at most 1000 records and 1000 deletions per batch, 4 MB request body. Exceeding
  them fails with `BAD_USER_INPUT`.

## Client behaviour

- Send at most 100 records or 512 KB per batch.
- Keep a batch queued until the acknowledgement's `batchId` matches. Retry with the same
  `batchId` and the same content.
- On `UNAUTHENTICATED`, stop syncing and surface that the client must be paired again.
- Report a record that disappeared from the origin as a deletion.

## Payload rules (Health Connect)

The payload is the Health Connect record as JSON.

- Keys are the Kotlin property names of the record class, in camelCase. Every property of
  the record is included, also when null.
- `Instant` is an ISO-8601 UTC string. `ZoneOffset` is `<name>Seconds` as an integer, for
  example `startZoneOffsetSeconds`.
- `Duration` is `<name>Millis` as an integer.
- Unit types are an object `{ "value": <number>, "unit": "<unit>" }` in one canonical unit:

  | Type               | Unit                   |
  | ------------------ | ---------------------- |
  | `Length`           | `meters`               |
  | `Mass`             | `kilograms`            |
  | `Energy`           | `kilocalories`         |
  | `Power`            | `watts`                |
  | `Volume`           | `liters`               |
  | `Pressure`         | `millimetersOfMercury` |
  | `Temperature`      | `celsius`              |
  | `TemperatureDelta` | `celsius`              |
  | `BloodGlucose`     | `millimolesPerLiter`   |
  | `Velocity`         | `metersPerSecond`      |
  | `Percentage`       | `percent`              |

- Integer constants keep their integer under the property name and add the constant's name
  under `<property>Name`, for example `"stage": 4, "stageName": "LIGHT"`. An integer with
  no known constant name gets `"<property>Name": null`.
- Nested lists (`samples`, `stages`, `segments`, `laps`, route locations) are arrays of
  objects following the same rules.
- A sealed class value (`ExerciseRouteResult`, `ExerciseCompletionGoal`,
  `ExercisePerformanceTarget`) is an object whose `"type"` is the subclass's simple name,
  followed by that subclass's properties, for example
  `{ "type": "Data", "exerciseRoute": { "route": [ … ] } }`,
  `{ "type": "DurationGoal", "durationMillis": 600000 }` or `{ "type": "ManualCompletion" }`.
- Properties keep their Kotlin name also when the JVM getter is renamed, for example
  `PlannedExerciseSessionRecord.hasExplicitTime`.
- `metadata` is always present:

  ```json
  {
    "id": "…",
    "dataOrigin": "com.example.app",
    "lastModifiedTime": "2026-11-14T10:00:00Z",
    "clientRecordId": null,
    "clientRecordVersion": 0,
    "recordingMethod": 1,
    "recordingMethodName": "ACTIVELY_RECORDED",
    "device": { "manufacturer": "…", "model": "…", "type": 1, "typeName": "WATCH" }
  }
  ```

  `dataOrigin` is the `DataOrigin.packageName` string, not an object. `device` is null when
  the origin did not record one.

`contracts/health-connect/v1/<RecordType>.json` holds one synthetic example payload per
record type. The Android serialiser has a test that reproduces each fixture; the API
projection has a test that consumes each fixture.
